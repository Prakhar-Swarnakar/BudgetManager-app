Add/Edit Transaction — tightening the layout

Today's screen stacks Title then Amount in separate rows, has a full boxed date field sitting mid-form after the Split section, and ends in a Cancel/Save button row at the very bottom of a long scrolling page - disconnected from the fields they act on. This mockup compares today's screen against a core redesign (the six changes already agreed), plus three optional add-ons shown separately so you can pick which, if any, to commission alongside it.

  • Core redesign - Title+Amount side by side, no bottom button row, Save moves into the top bar next to the header, the back arrow is the only way out (it already discards exactly like Cancel does today - no behaviour change there), and the boxed date field is replaced by a small tappable date line under the SMS text, opening the same calendar dialog as today. Ready to build as scoped.
  • Option 1 - collapse the "Add to rule" controls under Category/Payment method, since they only matter for a brand-new merchant.
  • Option 2 - auto-scroll to the first validation error when Save (now up top, away from the fields) fails.
  • Option 3 - a real "this will un-settle everyone" confirmation before saving an edited split transaction - docs/06-backlog.md says this already exists; it doesn't. Surfaced here since we're touching this exact Save path.
