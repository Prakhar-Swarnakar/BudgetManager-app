Root cause: `SpendClassifier.isSpendLike()`/`CreditClassifier.isCreditLike()` both required an amount pattern (`Rs`/`INR`/`₹` + digits) **and** a debit/credit keyword - a genuine SIP purchase confirmation ("Systematic Investment Purchase...has been processed") never states an amount inline, pointing to a separate statement instead, so it failed the amount check and was silently dropped by `SmsReceiver`/`DefaultInboxScanner`'s `else { continue }` - never stored, never visible, not even as Not assigned.
